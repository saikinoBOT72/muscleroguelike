# 筋トレ融合ローグライク 完全仕様書(実装用)

対象: ターン制カードバトル・ローグライク(スレイ・ザ・スパイア型構造を踏襲)
本書は「そのままコード化できる」ことを目的に、数値・アルゴリズム・データ構造まで全て明記する。

---

## 0. 種目 → カードカテゴリ 対応表

| # | 種目 | 部位/性質 | カードカテゴリ | 役割 |
|---|---|---|---|---|
| 1 | 腕立て伏せ | 胸・腕(プッシュ) | **ATTACK(攻)** | 直接ダメージ |
| 2 | ジャンプスクワット | 脚・瞬発力 | **SKILL(速)** | エナジー加速・回避・ドロー・テンポ |
| 3 | ツイストレッグレイズ | 体幹・回旋 | **DEBUFF(崩)** | 状態異常付与・小ダメージ |
| 4 | プランク | 体幹・等尺性保持 | **POWER(耐)** | ブロック・継続効果・持久 |

設計意図: 「捻る」動作は敵の体勢を崩すイメージでDEBUFFに、「保持し続ける」プランクは継続効果のPOWERに対応させている。4カテゴリが全てEnergy/Block/Damage/Statusという戦闘の4大要素をちょうど1つずつ担当する構成。

### 変換式(回数 → 生成カード枚数)
```
カード枚数 = floor( sqrt(回数 / 5) )   ※上限4枚/種目/日
```
| 回数 | 生成枚数 |
|---|---|
| 1〜4 | 0枚 |
| 5〜19 | 1枚 |
| 20〜44 | 2枚 |
| 45〜79 | 3枚 |
| 80〜 | 4枚(上限) |

- 平方根カーブにより「水増し連打」の得を逓減させる
- 生成されるカードのレアリティは枚数に応じて重み付け抽選(下記3章のレアリティ抽選表を使用)
- 0回の種目があってもBASICカード(後述1.1)で最低限のデッキは保証される

## 2. 状態異常(ステータスエフェクト)定義

| 名称 | 対象 | 効果 | 減衰 |
|---|---|---|---|
| 弱体(Weak) | 攻/敵 | 与えるダメージ -25% | 毎ターン開始時に1減少 |
| 脆弱(Vulnerable) | 攻/敵 | 受けるダメージ +50% | 毎ターン開始時に1減少 |
| 出血(Bleed) | 敵 | ターン終了時にスタック数分ダメージ、スタックは減少しない(能力で解除するまで持続) | 戦闘終了まで持続 |
| 力(Strength) | 味方 | ATTACKカードのダメージに+スタック数 | 永続(戦闘中) |

ダメージ計算式:
```
最終ダメージ = floor( (基礎ダメージ + 力) × (脆弱なら1.5倍) × (弱体なら0.75倍) )
```

## 5. マップ生成アルゴリズム

STS方式(グラフ型分岐マップ)を踏襲する。

### 5.1 構造
- 1ランは7行(Row)× 各行3〜4ノードのグラフ
- Row 0(スタート地点)から各ノードへ、Row 6(ボス部屋)まで経路が収束する
- 各ノードから次の行の隣接ノード(左・中央・右のうち到達可能なもの)へ1〜2本の辺を張る(交差OK、STS同様)

### 5.2 ノードタイプと出現率(Row 1〜5、Row0はスタート、Row6は必ずBOSS)
| タイプ | 出現率 | 制約 |
|---|---|---|
| COMBAT(通常戦闘) | 45% | - |
| EVENT(選択肢イベント) | 22% | 連続2回まで |
| REST(休憩所) | 12% | 直前がRESTなら再抽選、Row5の1つ前後には最低1つ配置を保証 |
| SHOP(ショップ) | 8% | ラン中最低1回は保証(未出現ならRow3付近に強制配置) |
| ELITE(中ボス) | 8% | Row2以降のみ出現、ラン中1〜2回に制限 |
| TREASURE(宝箱=レリック入手) | 5% | - |

### 5.3 生成擬似コード
```python
def generate_map(rows=7, cols=4):
    graph = init_empty_nodes(rows, cols)
    paths = generate_paths(rows, cols, path_count=6)  # 開始点から終点へのパスを複数生成、辺を確定
    for row in range(1, rows-1):
        for node in graph[row]:
            if node.has_incoming_edge:
                node.type = weighted_random(NODE_WEIGHTS, exclude=recent_types(node))
    graph[rows-1] = [BOSS_NODE]
    ensure_shop_exists(graph)
    ensure_rest_before_boss(graph)
    return graph
```

## 6. 戦闘ターンフロー(擬似コード)

```
戦闘開始:
    プレイヤーHP・敵HPをセット
    デッキをシャッフルしてDrawPileにする
    手札5枚をDrawPileから引く

ターン開始(プレイヤー):
    Energy = 3 にリセット
    Block = 0 にリセット(金剛の構え使用中は除く)
    Power系カードの「ターン開始時」効果を発動(継続する強さ、踏ん張り等)
    弱体/脆弱のスタックを1減少
    手札が5枚未満ならDrawPileから補充(DrawPileが尽きたらDiscardPileをシャッフルして補充)

プレイヤー行動:
    ループ: カードを選択 → Energy消費可能か判定 → 効果解決 → DiscardPile(またはExhaustPile)へ
    ターン終了を選択 or Energy切れ

敵ターン:
    各敵のIntentに従って行動(攻撃ならブロック計算後にHPへ反映)
    敵の「ターン終了時」効果を発動(出血ダメージ等)

勝敗判定:
    敵全滅 → 戦闘勝利 → 報酬画面(カード3択、ゴールド、まれにレリック)
    プレイヤーHP0 → 敗北 → 素材50%持ち帰り確定、ラン終了
```

## 11. 確定事項(旧「未決定」)

| 項目 | 決定 |
|---|---|
| プランク秒数→回数換算 | **2秒 = 1カウント**(`count = floor(plank_seconds / 2)`) |
| カード報酬3択のカテゴリ | **全カテゴリ均等**(4カテゴリから3つを重複なしで抽選し、各1枚ずつ提示) |
| 難易度 | **「ふつう」「むずい」の2段階**。むずいは敵性能・被ダメを明確に引き上げ、報酬倍率は **1.2倍** に留める |
| Ascension | むずいモードとは**別物**。Phase 9 の完成後に、むずいの上へ1段ずつ縛りを積む「むずい+1〜+5」のラダーとして**任意追加**(`docs/phase-10-ascension.md`)。報酬は増やさない |
| 敗北時ペナルティ | 筋力コアは **50%没収**(獲得量の50%のみ持ち帰り、端数切り上げ)。演出・救済メッセージは Phase 9 で実装 |

詳細な数値は `docs/phase-1-exercise-input.md`(換算・難易度選択)、
`docs/phase-6-nodes-rewards.md`(報酬抽選)、
`docs/phase-9-difficulty-polish.md`(難易度パラメータ)を参照。
