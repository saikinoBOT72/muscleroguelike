# Phase 10 —(任意)Ascension: むずい+1 〜 +5

## 位置づけ

**Phase 9 まで完成し、むずいのバランスが取れてから着手する追加要素。**
Phase 0〜9 の設計には一切影響させない。ここを実装しなくてもゲームは完成品として成立する。

> 着手前提: `docs/balance-log.md` に Phase 9 のバランス実測が記録済みであること。
> むずい(+0)のクリア率が 25〜35% に収まっていない状態でラダーを刻んでも数値が決められない。

---

## 1. 設計方針

- 「むずい」は**ふつうに対する縛り11項目の詰め合わせ**。Ascension はその上に
  **1段につき縛り1個ずつ**を積み増していく階段
- **物質的な報酬は増やさない**。ゴールド・筋力コアの倍率は むずい(+0)と同じ 1.2 のまま
  (+3 以降はむしろ減る)。純粋な腕試し枠であり、旨味で釣らない
- 見返りは**記録とバッジのみ**。`meta.maxAscensionCleared` を残し、タイトル画面に表示する
- 1段ずつ解放。飛び級はさせない

---

## 2. ラダー定義

`DIFFICULTY.HARD` のコピーに対して、レベル1から順に `apply` を累積適用する。

```js
const ASCENSION = [
  { lv:1, label:'エリート強化',
    desc:'エリートのHP+15%、エリートの開始時の力+1',
    apply:(d)=>{ d.eliteHpMult = 1.15; d.enemyStartStrength.ELITE += 1; } },

  { lv:2, label:'消耗戦',
    desc:'通常敵の開始時の力+1、中盤以降の敵編成が1行早まる',
    apply:(d)=>{ d.enemyStartStrength.NORMAL += 1; d.encounterShift = 1; } },

  { lv:3, label:'枯渇',
    desc:'カード報酬が3択→2択、ゴールド報酬×0.85',
    apply:(d)=>{ d.rewardChoices = 2; d.goldMult *= 0.85; } },

  { lv:4, label:'摩耗',
    desc:'最大HP-5、休憩の回復が最大HPの12%に',
    apply:(d)=>{ d.playerMaxHp -= 5; d.restHealRate = 0.12; } },

  { lv:5, label:'ボス覚醒',
    desc:'ボスのHP+15%、フェーズ2の閾値がHP75%に',
    apply:(d)=>{ d.bossHpMult = 1.15; d.bossPhase2 = 0.75; } },
];

function resolveDifficulty(key, asc){
  const d = deepClone(DIFFICULTY[key]);
  if (key !== 'HARD') return d;
  for (const a of ASCENSION) { if (a.lv <= asc) a.apply(d); }
  return d;
}
```

**以降、コード中の `DIFFICULTY[G.run.difficulty]` への直接参照を全て
`G.run.diff`(ラン開始時に `resolveDifficulty()` で確定させた実体)に置き換える。**
これが Phase 10 で最も破壊的な変更なので、最初にこの置換だけを済ませて
むずい+0 が今まで通り動くことを確認してから、レベル定義を足すこと。

### むずい+5 の実効値(参考)

| 項目 | ふつう | むずい+0 | むずい+5 |
|---|---|---|---|
| 最大HP | 70 | 60 | **55** |
| 通常敵HP / 力 | ×1.0 / 0 | ×1.25 / +1 | ×1.25 / **+2** |
| エリートHP / 力 | ×1.0 / 0 | ×1.25 / +2 | **×1.44** / **+3** |
| ボスHP / 力 | ×1.0 / 0 | ×1.25 / +2 | **×1.44** / +2 |
| ボスP2 閾値 | 50% | 60% | **75%** |
| 休憩の回復 | 30% | 20% | **12%** |
| カード報酬 | 3択 | 3択 | **2択** |
| ゴールド倍率 | ×1.0 | ×1.2 | **×1.02** |
| 筋力コア倍率 | ×1.0 | ×1.2 | ×1.2 |

## 3. 新規パラメータの適用箇所

Phase 10 で新しく増える 4 つのパラメータを、既存コードに差し込む。

| パラメータ | 既定値 | 適用箇所 |
|---|---|---|
| `eliteHpMult` | 1.0 | Phase 4 の敵生成。`tier==='ELITE'` のとき `enemyHpMult` に**乗算** |
| `bossHpMult` | 1.0 | 同上、`tier==='BOSS'` のとき |
| `encounterShift` | 0 | Phase 5 のマップ生成。`enemyGroup` 決定時の Row 判定を `row + encounterShift` で行う(Row3 で LATE 編成が出るようになる) |
| `rewardChoices` | 3 | Phase 6 の `pickRewardCards()`。`shuffle(cats).slice(0, rewardChoices)` |

> `rewardChoices` を 2 にしても**全カテゴリ均等の原則は維持される**
> (4カテゴリから重複なしで2つ抽選するだけ)。

## 4. 解放とセーブ

```js
meta.maxAscensionUnlocked = 0;   // 0 = むずい+0 のみ。むずいクリアごとに +1(上限5)
meta.maxAscensionCleared  = -1;  // -1 = むずい未クリア
```

- むずい(+N)をクリアしたとき: `maxAscensionCleared = max(現在値, N)`、
  `maxAscensionUnlocked = min(5, max(現在値, N+1))`
- **敗北では解放されない**
- そもそも「むずい」自体が Phase 8 の通り「ふつうを1回クリア」で解放される。
  ラダーはその先の話

### 既存セーブとの互換
Phase 9 までのセーブには上記2キーが無い。`loadGame()` で
`meta.maxAscensionUnlocked ??= 0`、`meta.maxAscensionCleared ??= -1` を補完すること。
セーブのバージョンキーは `mrog_save_v1` のまま変えない(破棄させない)。

## 6. バランス検証

各段階を最低1ランずつプレイする(+5 はクリアできなくてよい)。

| 段階 | 目標クリア率(体感) |
|---|---|
| むずい+0 | 25〜35% |
| むずい+2 | 15〜20% |
| むずい+5 | 5〜10%(**理論上はクリア可能**であること) |

「+5 が運ゲーでしかクリアできない」なら +4/+5 の縛りを緩める。
調整は `docs/balance-log.md` に記録する。
