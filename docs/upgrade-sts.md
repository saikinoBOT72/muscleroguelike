## 0. 何が足りていないか

### 0.1 根本原因 — デッキがランの前に確定している

規模の話をする前に、もっと深い問題がある。

**STS の面白さの中心は「ランの中でシナジーを見つけて組み上げていく」ことにある。**
報酬の3択を20回以上繰り返し、そのたびに「この方向に寄せるか」「デッキを薄く保つか」を選ぶ。
その積み重ねが1ランの物語になる。

現行版はこの構造が**成立していない**。
最大24枚のデッキのうち **16枚が運動入力の時点で確定**しており、
ランの中で足せるのは報酬4〜5枚だけ。
プレイヤーは「配られた山を回す」だけで、**組み上げる余地がない**。

これは戦闘回数を4.6→24に増やしても解決しない。
デッキが最初から決まっているなら、幕が3つになっても「引きが強い日か弱い日か」でしかない。

> **本改訂の中心は、運動記録の役割を「デッキそのもの」から「ビルドの土台」に変えること。**
> 2章でこれを扱う。規模の拡張(3幕化)はその次に重要な施策として3章以降で扱う。

### 0.2 規模

現行版を STS と比較した実測値:

| | 現行版 | STS | 本改訂の目標 |
|---|---|---|---|
| 1ランで踏むノード | 7.0 | 約45〜48 | **36** |
| 1ランの戦闘回数 | 4.6 | 約40 | **約24** |
| カード総数 | 37 | 約75+35 | **73** |
| レリック | 6 | 180以上 | **30** |
| 敵の種類 | 9(定義10) | 50以上 | **27(定義28)** |
| ポーション | なし | 約50種・3枠 | **18種・3枠** |
| 呪い / 状態異常カード | なし | あり | **8種** |
| ブロック側のデバフ | なし | 虚弱・敏捷 | **追加** |
| 手札操作キーワード | Exhaust のみ | Retain / Ethereal / Innate ほか | **追加** |

問題の本質は**規模**である。4.6戦ではデッキ構築の物語が起きる前にランが終わる。
本改訂は「戦闘の中身」ではなく「ランの長さと選択肢の幅」を STS 級に引き上げる。

### 方針

1. **運動記録を「デッキ」から「ビルドの土台」に作り替える**(2章)。これが最優先。
   デッキの大半をラン中に組めるようにして、STS の構築アークを取り戻す
2. **1幕 → 3幕**にする(3章)。構築アークが起きるだけの回数を確保する
3. **選択肢の幅**を増やす(カード2倍、レリック5倍、ポーション新規、呪い新規)
4. **運動の影響は弱めるのではなく、効き方を変えて強める**。
   カード枚数ではなく「何が引けるか」「どこまで伸びるか」を運動が決める
5. 既存の実装済みシステム(戦闘コア・マップ生成・レリックフック・メタ進行)は
   **壊さずに拡張する**。互換のためのセーブ移行も定義する

### プレイ時間について(トレードオフの明示)

3幕 × 12行 = 36ノードで、1ラン **45〜70分**を見込む。
現行の 15〜25分から大幅に伸びるため、「毎日その日の運動記録で1ラン」という前提とは
やや噛み合わなくなる。これは「STS に近づける」ことのコストとして受け入れる前提で設計している。

短くしたい場合、`ROWS_PER_ACT` の1定数だけで調整できるようにする(12 → 8 で約30〜45分)。
逆に STS 完全準拠にしたい場合は 15 にする(約90分)。

## 2. 運動記録の再設計 — 「デッキ」から「ビルドの土台」へ

本改訂の中心。**筋トレの実際のロジックをそのままゲームの構造に写す。**

### 2.1 考え方

現行は「回数 → カード枚数」の一本だけだった。これを4つに分ける。

| 軸 | 筋トレでの意味 | ゲームでの効果 |
|---|---|---|
| **深さ** | 鍛えた部位しか使えない | 種目ごとの回数が、**そのカテゴリで報酬に出るカードのレアリティ上限**を決める |
| **型** | 部位分割法(その日は何の日か) | 最も回数の多い種目が「今日の型」。開始レリックと報酬の出やすさが変わる |
| **体力** | 総ボリューム(セット×レップ) | 総回数が **最大HP・手札枚数・開始ゴールド** を決める |
| **成果** | その日やった分だけ身についたもの | 種目ごとに**1枚だけ**、深さに応じたカードがデッキに入る |

初期デッキは **8枚に戻す**(仕様書どおり: パンチ×3、ガード×3、サイドステップ×1、フェイント×1)。
成果カードは最大4枚なので、**ラン開始時のデッキは 8〜12枚**。STS の10枚とほぼ同じで、
デッキの大半をラン中の報酬で組み上げることになる。

---

### 2.2 深さ — 鍛えていない部位は使えない

種目ごとの `count`(プランクは2秒=1カウント)が、**そのカテゴリで報酬・ショップ・イベントに
出現しうるカードのレアリティ上限**を決める。

| その種目の count | そのカテゴリで出現するカード | 意味 |
|---|---|---|
| 0〜4 | **出現しない** | 鍛えていない部位は使えない |
| 5〜24 | COMMON まで | 動かした |
| 25〜79 | UNCOMMON まで | 鍛えた |
| 80〜 | **RARE まで** | 追い込んだ |

```js
const DEPTH_TIERS = [
  { min:  0, cap: null },        // 出現しない
  { min:  5, cap: 'COMMON' },
  { min: 25, cap: 'UNCOMMON' },
  { min: 80, cap: 'RARE' },
];
function depthCap(count){
  let cap = null;
  for (const t of DEPTH_TIERS) if (count >= t.min) cap = t.cap;
  return cap;                     // null なら そのカテゴリは抽選対象外
}
const RARITY_RANK = { COMMON:1, UNCOMMON:2, RARE:3 };
function inDepth(cardId){
  const c = CARDS[cardId];
  if (c.rarity === 'BASIC') return true;
  const cap = G.run.depth[c.cat];
  return cap != null && RARITY_RANK[c.rarity] <= RARITY_RANK[cap];
}
```

`run.depth = { ATTACK:'RARE', SKILL:'COMMON', DEBUFF:null, POWER:'UNCOMMON' }` のように保持する。

**適用箇所**(`isUnlocked()` と AND で組み合わせる):
- カード報酬(`pickRewardCards`)
- ショップの在庫(`makeShopStock`)
- イベントの「カード1枚獲得」
- 祝福「見識」の RARE 3択

> **これが最も強く効く仕組み。** 腕立てをしていない日は ATTACK のカードが1枚も報酬に出ない。
> デッキはランの中で組むが、**何を組めるかは今日の運動が決めている**。
>
> 全カテゴリが 0〜4 になる(=何も運動していない)場合のみ、
> 全カテゴリを COMMON まで解禁する(ゲームが成立しなくなるため)。
> ただしこのとき **体力も型もボーナスが一切付かない**ので、実質的な最低難度スタートになる。

**これが「全カテゴリ均等」を撤廃できる理由でもある。**
報酬側で均等にしなくても、入力側が「引けるカテゴリ」を決めているので、
偏った運動をすれば自然に偏ったデッキになり、全部やれば全部から引ける。

---

### 2.3 型 — 今日は何の日か

`count` が最も多い種目が「今日の型」。ラン開始時に専用レリックを1つ得て、
そのカテゴリのカードが報酬に出る確率が上がる。

| 型 | 条件 | 開始レリック | 報酬での優遇 |
|---|---|---|---|
| **押しの型** | 腕立てが最多 | 鍛錬の証(戦闘開始時 力+1) | ATTACK の出現重み ×1.5 |
| **跳ねの型** | ジャンプスクワットが最多 | 加速装置(最初のターン Energy+1) | SKILL の出現重み ×1.5 |
| **捻りの型** | ツイストレッグレイズが最多 | 執念の記録(出血ダメージ+50%) | DEBUFF の出現重み ×1.5 |
| **支えの型** | プランクが最多 | 不屈のプレート(戦闘開始時 ブロック+5) | POWER の出現重み ×1.5 |
| **総合の型** | 最多が2種目以上で並ぶ | なし。代わりに **最大HP+10** | 優遇なし(4カテゴリ均等) |

- 全種目0のときは型なし
- 型のレリックは**メタ進行のアンロックを無視して必ず手に入る**(型が確実に効くようにするため)
- 型のレリックが既に他経路で手に入っている場合は、代わりにゴールド+80

`run.form = 'ATTACK' | 'SKILL' | 'DEBUFF' | 'POWER' | 'BALANCED' | null`

報酬抽選での重み付け:

```js
function categoryWeight(cat){
  return (G.run.form === cat) ? 1.5 : 1.0;
}
```

### 2.4 体力 — 総ボリューム

```js
volume = ATTACK count + SKILL count + DEBUFF count + POWER count
```

| volume | 最大HP | 手札枚数 | 開始ゴールド |
|---|---|---|---|
| 0〜19 | 70 | 5 | 99 |
| 20〜59 | 75 | 5 | 110 |
| 60〜119 | 80 | 6 | 125 |
| 120〜239 | 85 | 6 | 145 |
| 240〜 | **90** | **7** | **170** |

むずいは各段階の最大HPから **-10**(70→60 … 90→80)。

```js
const VOLUME_TIERS = [
  { min:   0, maxHp:70, hand:5, gold: 99 },
  { min:  20, maxHp:75, hand:5, gold:110 },
  { min:  60, maxHp:80, hand:6, gold:125 },
  { min: 120, maxHp:85, hand:6, gold:145 },
  { min: 240, maxHp:90, hand:7, gold:170 },
];
```

> 現行の「生成カード枚数で手札が増える」仕組みは廃止し、**総ボリューム**に置き換える。
> 「たくさん動いた日は体力がある」という直感どおりの効き方になる。

`MAX_HAND` は 12 のまま(手札上限7 + 保持カードの余裕)。

### 2.5 成果カード — その日やった分だけ身についたもの

種目ごとに **最大1枚**、深さに応じたレアリティのカードがデッキに入る。

| その種目の count | 生成 |
|---|---|
| 0〜4 | なし |
| 5〜24 | COMMON 1枚 |
| 25〜79 | UNCOMMON 1枚 |
| 80〜159 | RARE 1枚 |
| 160〜 | **RARE 1枚(強化 + 版)** |

初期デッキ8枚 + 成果カード0〜4枚 = **8〜12枚**。

```js
function buildDeck(exercise, meta, diffKey){
  const deck = STARTING_DECK.map(id =>
    newCardInstance(id, meta.upgradedBasics.includes(id)));
  const counts = normalizeExercise(exercise);
  for (const ex of EXERCISES){
    const n = counts[ex.cat];
    const cap = depthCap(n);
    if (!cap) continue;
    const id = rollCardOf(ex.cat, cap, deck, []);
    if (id) deck.push(newCardInstance(id, n >= 160));
  }
  return deck;
}
```

> 現行の「最大16枚生成」を廃止する理由は 0.1章のとおり。
> デッキを運動で埋めてしまうと、ランの中で組む余地が消える。
> **運動は「何を組めるか(深さ)」「どこまで伸びるか(体力)」「どちらに寄るか(型)」で効かせ、
> デッキそのものは STS と同じくランの中で作る。**

### 2.6 超回復 — 休むことが強くする

休憩所の「休む」を**超回復**に変える。

| 選択肢 | 効果 |
|---|---|
| 🔥 **超回復** | HPを最大HPの30%(むずい22%)回復。**さらに次の戦闘のみ 力+1、敏捷+1** |
| ⚒ 鍛える | デッキから1枚を Upgrade(変更なし) |

`run.superCompensation = true` を立て、次の `startBattle()` で
`B.status.strength += 1; B.status.dexterity += 1` して false に戻す。

> 筋トレで最も基本的な原則。「休んだ分だけ強くなる」を、
> 回復量だけでなく**次の戦闘の強化**として体感させる。
> 「鍛える」を選ぶか「休む」を選ぶかが、単なるHP管理より深い選択になる。

### 2.7 漸進性過負荷 — 幕ごとに要求が上がる

3章の `ACT_SCALE` はこの原則の実装。UI で明示する。

- 幕の開始時に「**第2幕 — 漸進性過負荷: 敵のHP +15% / 攻撃力 +10%**」と表示する
- HUD の幕バッジをタップすると、現在の幕倍率が確認できる

> 「同じ重量を続けても強くならない、毎回少しずつ上げる」という原則を、
> 幕ごとの敵の強化として明示的に見せる。

### 2.8 セット — 同じ動作を繰り返す

一部のカードに「このターン、同じカードを使うのが2回目以降なら効果+」を持たせる。
新しい effect フィールド `setBonus` として実装する。

```js
{ type:'damage', value:6, setBonus:3 }   // 同名カードのこのターン2回目以降は 9
```

`B.playedThisTurn = { cardId: count }` を持ち、`playCard()` の先頭で加算する。
対象カードは Phase 13 で3枚に限定する(`atk_double_punch` / `atk_rush` / `skl_dash`)。

> 「1セット目より2セット目のほうが効く」わけではないが、
> **同じ動作を反復することが力になる**という筋トレの手触りをカードに落とす。

### 2.10 初期デッキの差し替え(BASIC 8種の入手経路)

初期デッキを8枚に戻すと、`ダブルパンチ` `ダッシュ` `鋭い視線` `踏ん張り` の4種が
**どこからも入手できなくなる**(BASIC は生成・報酬・ショップの抽選対象外のため)。
Phase 9 ではこれを「初期デッキを12枚にする」ことで解決したが、
2.5章のとおりデッキを薄く保つ方針に変えたので、別の経路を用意する。

**強化所の「初期デッキ」タブを、差し替え式にする。**

| 現在の枠 | 差し替え候補 | コスト |
|---|---|---|
| パンチ ×3 のうち1枚 | ダブルパンチ | 胸コア 10 |
| ガード ×3 のうち1枚 | 踏ん張り | 体幹コア 10 |
| サイドステップ | ダッシュ | 脚コア 10 |
| フェイント | 鋭い視線 | 捻転コア 10 |

- 差し替えは**いつでも元に戻せる**(コストは初回のみ。以降は無料で切り替え)
- 既存の「BASIC を恒久 Upgrade(コア12)」はそのまま残す。差し替えた側も個別に強化できる
- `meta.deckSwaps = { atk_punch:'atk_double_punch', ... }` で保持し、
  `buildDeck()` の初期デッキ生成時に適用する

```js
const BASIC_SWAPS = [
  { slot:'atk_punch',    to:'atk_double_punch', core:'chest', cost:10 },
  { slot:'pwr_guard',    to:'pwr_brace',        core:'core',  cost:10 },
  { slot:'skl_sidestep', to:'skl_dash',         core:'leg',   cost:10 },
  { slot:'dbf_feint',    to:'dbf_sharp_gaze',   core:'twist', cost:10 },
];
```

> 「初期デッキを自分で組む」というメタ進行の軸が新しく生まれる。
> STS には無い要素だが、**毎日遊ぶゲームとして「自分の型を作る」感触**になるので採用する。

## 3. ラン構造 — 3幕 × 12行

### 3.1 定数

```js
const ACTS = 3;
const ROWS_PER_ACT = 12;      // Row 0..11。Row11 が幕ボス
const MAP_COLS = 4;           // 変更なし
```

`run.act`(1〜3)を追加し、`run.map` は**幕ごとに再生成**する。
マップは1幕分だけ保持する(3幕分を同時に持たない)。

### 3.2 各幕の行構成

| Row | 内容 |
|---|---|
| 0 | スタート(必ず COMBAT、2〜3ノード) |
| 1〜10 | 重み抽選 |
| 11 | 幕ボス(1ノードに収束) |

パス本数は 6 → **8** に増やす(行が増えるとノードが痩せるため)。

### 3.3 ノード出現率(幕共通)

現行の `NODE_WEIGHTS` を据え置く。ただし制約補正を行数に合わせて更新する。

| 制約 | 変更後 |
|---|---|
| Row1 は ELITE / REST 禁止 | 変更なし |
| ELITE は Row2 以降 | 変更なし |
| ELITE の個数 | **1幕あたり 2〜4個**(現行 1〜2) |
| SHOP の個数 | **1幕あたり 1〜2個** |
| REST は連続禁止 | 変更なし |
| EVENT は連続2回まで | 変更なし |
| ボス直前(Row10)に REST 保証 | 変更なし |
| **(新規)到達可能性の保証** | **SHOP と REST は、Row0 から到達できる経路上に必ず1つ以上存在すること** |

> **到達可能性の保証は新規の必須要件。** 現行実装は「マップ上に存在する」しか保証しておらず、
> 実測でショップに入れるランは 50%、休憩は 62%、エリート遭遇は 39% しかなかった。
> 行数が増えれば自然に緩和されるが、明示的に保証する。
>
> 実装: 生成後に「Row0 の各ノードから到達可能なノード集合」を BFS で求め、
> その集合内に SHOP / REST が無ければ、集合内のランダムなノードを置換する。

### 3.4 幕ごとの難度スケーリング

幕別の敵プール(17章)に加え、幕倍率を掛ける。

```js
const ACT_SCALE = {
  1: { hpMult: 1.00, dmgMult: 1.00, goldMult: 1.0 },
  2: { hpMult: 1.15, dmgMult: 1.10, goldMult: 1.2 },
  3: { hpMult: 1.30, dmgMult: 1.20, goldMult: 1.5 },
};
```

敵生成時の HP: `round(baseHp * difficulty.enemyHpMult * ACT_SCALE[act].hpMult)`
敵の攻撃力: `floor(value * difficulty.enemyDmgMult * ACT_SCALE[act].dmgMult)`
戦闘報酬ゴールド: `floor(base * difficulty.goldMult * ACT_SCALE[act].goldMult)`

### 3.5 幕の切り替え

4. 最大HPの **5%** 回復(切り上げ)
5. `run.act++`、`run.map = generateMap(...)`、`run.currentRow = -1`
6. 3幕目のボスを倒したら VICTORY

幕の切り替えは専用画面 `ACT_CLEAR` を挟む(「第1幕 突破」の表示 + 上記報酬)。

## 4. 状態異常とキーワードの拡張

### 4.1 状態異常一覧(11種)

| 名称 | key | 対象 | 効果 | 減衰 | アイコン |
|---|---|---|---|---|---|
| 弱体 | `weak` | 両方 | 与えるダメージ ×0.75 | 自ターン開始時 -1 | 🌀 |
| 脆弱 | `vulnerable` | 両方 | 受けるダメージ ×1.5 | 自ターン開始時 -1 | 💥 |
| 力 | `strength` | 両方 | ATTACKカードのダメージ +スタック | 永続 | 💪 |
| **敏捷** | `dexterity` | 両方 | **得るブロック +スタック** | 永続 | 🍃 |
| **虚弱** | `frail` | 両方 | **得るブロック ×0.75** | 自ターン開始時 -1 | 🥀 |
| 出血 | `bleed` | 両方 | ターン終了時にスタック分ダメージ(ブロック無視)、**その後 -1** | ターン終了時 -1 | 🩸 |
| **棘** | `thorns` | 両方 | **攻撃を受けるたび、攻撃者にスタック分ダメージ** | 永続 | 🌵 |
| **再生** | `regen` | 両方 | **ターン終了時にスタック分回復、その後 -1** | ターン終了時 -1 | 🌱 |
| **金属化** | `metallicize` | 両方 | **ターン終了時にスタック分ブロック獲得** | 永続 | ⚙ |
| **アーティファクト** | `artifact` | 両方 | **次に受けるデバフ1回を無効化し、スタック -1** | 消費時 -1 | 🔮 |
| **激昂** | `rage` | 両方 | **ATTACKカードを使うたびスタック分ブロック獲得** | ターン終了時に0 | 🔥 |

「デバフ」= `weak` / `vulnerable` / `frail` / `bleed` の付与、および `strength` / `dexterity` の**減少**。
アーティファクトはこれらを1回打ち消す。

### 4.2 出血の仕様変更(重要)

**現行**: スタックは減衰せず、戦闘終了まで毎ターン同じダメージを与え続ける。
**変更後**: STS の毒と同じく、ダメージを与えた後にスタックが1減る。

理由: 1幕4.6戦なら破綻しないが、3幕24戦になると非減衰出血が青天井に強くなる。
また STS に近づけるという本改訂の目的に照らしても、減衰する方が正しい。

**補償**: 出血を付与する既存カードの付与量を引き上げる(5.2章)。

### 4.3 ダメージ計算式(更新)

```
最終ダメージ = floor( (基礎ダメージ + 力) × (脆弱なら1.5) × (弱体なら0.75) )
```
変更なし。力は `type:'attack'` のカードにのみ乗る(既存どおり)。

**ブロック計算式(新規)**

```
獲得ブロック = floor( (基礎ブロック + 敏捷 + 完全防御ボーナス) × (虚弱なら0.75) )
```

`gainBlock(v)` を上記に置き換える。レリックの `onGainBlock` フックは虚弱適用後に呼ぶ。

### 4.4 キーワード

| キーワード | フィールド | 挙動 |
|---|---|---|
| 除外 | `exhaust: true` | 使用後 ExhaustPile へ(既存) |
| 場残り | `keep: true` | 使用後 powers[] へ(既存) |
| **保持** | `retain: true` | **ターン終了時に捨て札へ送られず、手札に残る** |
| **霊質** | `ethereal: true` | **ターン終了時に手札にあると、捨て札ではなく除外される** |
| **先天** | `innate: true` | **戦闘開始時、必ず初手に入る**(初期ドローの前に手札へ移す) |
| **使用不可** | `unplayable: true` | **プレイできない。コスト表記は「-」** |

複合可(例: 呪い「慢性疲労」は `unplayable + 除外不可`)。

**除外不可** (`unexhaustable: true`): 呪い専用。除外効果の対象外になる。

### 4.5 ターン終了処理の順序(更新)

```
endPlayerTurn():
  1. 反発(reflect)の解決
  2. 金属化: metallicize スタック分のブロック獲得
  3. 手札の処理:
       ethereal のカード → ExhaustPile
       retain のカード   → 手札に残す
       それ以外          → DiscardPile
  4. 敵ターンへ

enemyTurn() 終了時:
  5. 各敵の出血: スタック分ダメージ(ブロック無視) → スタック -1
  6. 各敵の再生: スタック分回復 → スタック -1
  7. プレイヤーの出血 / 再生も同様に処理
```

### 4.6 状態異常の付与とアーティファクト

```js
function applyStatus(entity, key, value){
  const isDebuff = ['weak','vulnerable','frail','bleed'].includes(key)
                || ((key === 'strength' || key === 'dexterity') && value < 0);
  if (isDebuff && (entity.status.artifact || 0) > 0){
    entity.status.artifact--;
    log('[アーティファクト] デバフを無効化した');
    return false;
  }
  entity.status[key] = (entity.status[key] || 0) + value;
  return true;
}
```
既存の `effects[].type === 'status'` は全てこの関数を経由させる。

### 4.7 棘の処理

`dealDamageToPlayer(amount, source)` の中で、プレイヤーの `thorns > 0` なら
`source` に `thorns` スタック分のダメージ(力・弱体・脆弱の影響を受けない固定値)。
敵側も `dealDamageToEnemy` で同様(攻撃元がプレイヤーの場合のみ)。
カードの「攻撃」が対象で、反射・出血・棘自身は棘を誘発しない。

## 6. カード報酬の変更 — 全カテゴリ均等を撤廃

### 現行(撤廃する)

4カテゴリをシャッフルして3つ取り、各カテゴリから1枚ずつ提示していた。
毎回必ず異なる3カテゴリが出るため、**特化ビルドを組もうとしても常に2/3が無関係なカテゴリ**になり、
デッキが平均化される方向に働いていた。STS はキャラのプール全体からランダムに引く。

### 変更後

カテゴリの制約は**報酬側では一切かけない**。代わりに 2章の「深さ」と「型」が効く。

```
pickRewardCards(difficulty, tier, count = 3):
  pool = 全カード
         - BASIC / 状態異常 / 呪い を除外
         - アンロック済(メタ進行)のみ
         - inDepth(id) を満たすもののみ        ← 2.2章「深さ」
  result = []
  for i in 0..count-1:
     rarity = weightedPick(REWARD_RARITY[difficulty])
     if tier != 'COMBAT' and rarity == 'COMMON': rarity = 'UNCOMMON'
     cand = pool の (rarity 一致 かつ result に未出現)
     if cand が空: rarity を1段下げて再試行(それでも空なら pool 全体から)
     card = weightedPick(cand.map(c => ({ v:c, w: categoryWeight(c.cat) })))   ← 2.3章「型」
     result.push(card)
  return result
```

- 同じカテゴリが3枚並ぶこともある(STS と同様)
- `REWARD_RARITY` の重みは据え置き(ふつう 65/25/10、むずい 62/25/13)
- `categoryWeight` は「今日の型」のカテゴリだけ 1.5、それ以外 1.0

### なぜ均等ルールを撤廃できるか

「4種目全部やらせる」という健康面の狙いは、報酬ではなく**入力側**が担保する。

| 入力 | 結果 |
|---|---|
| 腕立てだけ200回 | ATTACK は RARE まで出る。**SKILL / DEBUFF / POWER は1枚も出ない**。
ブロックもドローもデバフも無いデッキで3幕を戦うことになる |
| 4種目とも50回 | 全カテゴリ UNCOMMON まで。バランス型で戦える |
| 4種目とも100回 | 全カテゴリ RARE まで + 体力ボーナス。最も強い |

**偏らせれば偏ったデッキになり、それが弱いなら偏らせた本人の責任**という構造になる。
報酬側で均等を強制するより、はるかに直接的に「全部やる」動機になる。

同カテゴリの報酬に含まれるショップ・イベントの取得も同じ `inDepth()` を通す。

## 7. 状態異常カードと呪い(8種)

デッキが汚れる手段。現行版には存在せず、イベントの「リスクを取る」軸が丸ごと欠けていた。

### 7.1 共通仕様

- `cat: 'STATUS'` / `cat: 'CURSE'`。**4カテゴリのいずれにも属さない**
- 生成・報酬・ショップの抽選対象外(`isUnlocked` 以前に候補から除く)
- 全て `unplayable: true`(プレイできない。コスト表記は「-」)
- カード枠は灰色(STATUS)/ 紫黒(CURSE)。既存の `cat-*` とは別クラス `cat-STATUS` / `cat-CURSE`
- **STATUS は戦闘中に増える**(敵の攻撃・カード効果)。戦闘終了でデッキから消える(`run.deck` には入らない)

## 12. 運動入力の変更

**2章に統合した。** 生成枚数の上限引き上げ案(4→6枚)は撤回する。
デッキを運動で埋めると STS の構築アークが起きなくなるため、逆に **1枚/種目(最大4枚)** に絞り、

### 13.4 セーブ互換

セーブキーは `mrog_save_v1` のまま変えない(既存プレイヤーのコアを失わせない)。
`loadGame()` で以下を補完する。

```js
G.meta.unlockedPotions   ??= [];
G.meta.unlockedBossRelics ??= [];
G.meta.maxAct            ??= 1;
G.meta.deckSwaps         ??= {};
G.meta.swapsPurchased    ??= [];
if (G.run){
  G.run.act          ??= 1;
  G.run.potions      ??= [null, null, null];
  G.run.bossRelics   ??= [];
  G.run.blessing     ??= null;
  G.run.bonusEnergy  ??= 0;
  G.run.actCleared   ??= [];
  G.run.superCompensation ??= false;
  // depth / form / volume は旧ランには存在しない。復元できないので破棄対象
  if (G.run && !G.run.depth) G.run = null;
  // 旧マップ(7行)は構造が違うため、進行中のランは破棄してタイトルへ戻す
  if (G.run.map && G.run.map.rows.length !== ROWS_PER_ACT) G.run = null;
}
```

> 進行中の旧ランは復元できない(行数が変わるため)。
> タイトルで「前回のランは新バージョンに引き継げませんでした」と1度だけ表示する。

## 14. バランス目標

Phase 18 で `docs/balance-log.md` の手順(200ラン×条件のシミュレーション)で再測定する。

| 指標 | ふつう | むずい |
|---|---|---|
| クリア率(シミュレーション) | 45〜60% | 15〜25% |
| 第1幕クリア率 | 85%以上 | 60%以上 |
| 第2幕クリア率 | 65%以上 | 35%以上 |
| ボス到達時HP | 40〜70% | 25〜50% |
| 1ランの所要時間 | 45〜70分 | 45〜70分 |
| 最終デッキ枚数 | 28〜40枚 | 28〜40枚 |
| **運動0回 と 各種目100回 のクリア率差** | **25ポイント以上** | **25ポイント以上** |
| **1種目特化(200回×1)と 均等(50回×4)のクリア率** | 均等が10〜25ポイント上 | 同左 |

最後の2行が最重要。

- **運動量とクリア率が単調増加すること。** Phase 9 で一度これが 0 になり、ゲームの根幹が壊れていた
- **偏った運動より均等な運動のほうが強いこと。** 2.2章「深さ」が効いていれば自然にそうなる。
  逆に1種目特化が均等より強い場合、深さの制限が緩すぎるか、
  そのカテゴリ単独で完結できてしまっている(要バランス調整)

調整のたびに両方を必ず確認し、`docs/balance-log.md` に記録する。

### 調整の優先順位

1. `ACT_SCALE` の幕倍率
2. `DIFFICULTY` の難易度倍率
3. 幕別の敵プールと編成
4. ポーションのドロップ率
5. カード個別の数値(最後の手段。変更したら本書も更新する)

## 16. この改訂で STS との差が残るもの

正直に記録しておく。以下は本改訂の範囲外。

| 項目 | STS | 本改訂後 | 理由 |
|---|---|---|---|
| キャラクター | 4人、機構が別物(オーブ / スタンス / 毒) | 1つのデッキに4カテゴリ混在 | **運動→カテゴリ**がこのゲームの根幹なので変えられない |
| カード総数 | 約110(1キャラ分 + 無色) | 81 | 実装コスト。将来の拡張枠 |
| レリック | 180以上 | 30 | 同上 |
| 敵 | 50以上 | 27 | 同上 |
| Ascension | 20段 | ふつう/むずいの2段(Phase 10 で+5段の案あり) | `docs/phase-10-ascension.md` 参照 |
| 第4幕 / 真エンド | あり | なし | — |
| カードのX コスト | あり | `damageAllPerEnergy` で部分的に代替 | UI が複雑になるため |
| デッキ操作の深さ | Scry / 山札操作 / Retain の組合せ | Retain のみ | UI が複雑になるため |

**最も大きく残る差は「キャラクターによるビルドの分岐」**である。
STS はキャラを選んだ時点で別ゲームになるが、本作は常に4カテゴリの混成デッキになる。
これはコンセプト由来なので、代わりに**運動の配分**(腕立てだけやる=ATTACK特化)で
ビルドの分岐を出す設計になっている。Phase 13 で報酬の均等ルールを撤廃するのは、
この「配分によるビルド分岐」を報酬が邪魔しないようにするためでもある。
